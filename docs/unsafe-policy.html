Unsafe code policy

tpt-benchmark keeps its unsafe surface as small as possible.

Rules

  1. tpt-benchmark has #![deny(unsafe_code)] at the crate root. A module may opt in with #[allow(unsafe_code)], and only the modules listed below do. tpt-benchmark-macros and tpt-site have no unsafe and use #![forbid(unsafe_code)].
  2. Every unsafe block carries a // SAFETY: comment that states the invariant it relies on and why it holds.
  3. Every pub unsafe fn documents its preconditions in a # Safety section. The crate has none. The unsafe fn methods of the GlobalAlloc impl take their contract from that trait.
  4. unsafe_op_in_unsafe_fn is denied workspace-wide, so an unsafe operation inside an unsafe fn still needs its own block and comment.
  5. New unsafe needs a test or a documented reason it cannot be tested.
  6. Prefer a safe standard-library API when the MSRV allows it. (The no-op waker used to be hand-written unsafe; it is now Waker::noop(), stable from 1.85.)

Inventory

Audited on 2026-11-23 against the rules above. The audit was a manual review of every site, plus the checks listed under "How each is verified".

Findings from the audit, and what changed

  • Removed one unsafe block. The hand-written RawWaker in Bencher::iter_async is now Waker::noop().
  • Corrected the RDTSC justification. It said "no preconditions". It can fault when user-space RDTSC is disabled, which is now stated.
  • Tightened the CNTVCT_EL0 read by dropping nomem (see the table).
  • Made hardware counters thread-bound in the type system. The counter follows the thread that opened it, so reading it from another thread would silently measure the wrong thread. HardwareCounter is now neither Send nor Sync, on every platform, with a compile_fail doctest. Making that possible meant removing the Send + Sync supertrait from MeasurementLayer, which the crate never needed.
  • Pinned the kernel ABI size of PerfEventAttr with a unit test.
  • Added forbid(unsafe_code) to the macros crate and tpt-site.

Known limitations

  • RDTSC can fault. Where user-space RDTSC is disabled, for example after prctl(PR_SET_TSC, PR_TSC_SIGSEGV) or under some sandboxes and record-and-replay tools, the first read raises SIGSEGV. The crate does not detect this. There is no switch to force the Instant clock yet. Constructing Clock::instant() directly avoids it.
  • Counter reads are not serialised. Neither RDTSC nor mrs CNTVCT_EL0 is ordered against earlier instructions by the CPU, so a read can complete slightly before the work it follows. Batches last at least 1 ms by default, so the effect is far below the measurement noise. It would matter for a single very short timing, which this crate does not do.
  • A leaked fd on an unreachable path. If perf_event_open returned a value that does not fit a c_int, the descriptor would not be closed. The kernel never returns one, so this is not handled.
  • Perf counters have been exercised on Linux only as far as opening. See below.
