Timing overhead

Measured with cargo run --release -p tpt-benchmark --example overhead on Windows 11 (x86_64, invariant TSC). Numbers vary by CPU and OS, so rerun the example on your target before relying on them.

ClockOne readAmortised per iteration, N = 1N = 10N = 1 000N = 100 000
TSC~6.5 ns8.8 ns0.95 ns0.14 ns0.11 ns
Instant~27 ns26 ns2.6 ns0.14 ns0.11 ns

The batched loop divides one start/end read pair by N. The calibration (min_batch, 1 ms by default) grows N until a batch takes at least that long, so in practice N is large and the overhead is well under 1 ns per iteration. The floor of about 0.11 ns is the cost of the empty loop itself.

The TSC is used only when CPUID reports an invariant TSC and the calibrated rate agrees with the wall clock. Otherwise the layer falls back to Instant.

Built with tpt-benchmark. Hosted CI runners are noisy and usually have no hardware counters, so compare trends on one machine rather than absolute numbers.
