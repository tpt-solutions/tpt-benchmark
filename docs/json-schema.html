JSON export schema

tpt-benchmark writes its raw statistical data to target/tpt-benchmark/tpt-benchmark.json after every run. The document is versioned, so CI tooling can check it before reading it.

Current schema version: 2. The matching Rust constant is tpt_benchmark::json::SCHEMA_VERSION.

Top level

FieldTypeMeaning
schema_versionintegerSchema version. Increases on any incompatible change.
toolstringAlways "tpt-benchmark".
tool_versionstringVersion of the crate that wrote the file.
environmentobjectMachine and build the run was measured on (new in v2). See below.
benchmarksarrayOne entry per benchmark that ran. See below.

Environment

Added in schema 2. Every probe is best effort, so a field that could not be determined is null.

FieldTypeMeaning
commitstring or nullGit commit hash. GITHUB_SHA if set, else git rev-parse HEAD.
timestampstringUTC time the run finished, RFC 3339 (2026-11-23T04:05:06Z).
osstringlinux, macos, windows, ... (std::env::consts::OS).
archstringx86_64, aarch64, ... (std::env::consts::ARCH).
cpustring or nullCPU model name (/proc/cpuinfo, sysctl, or PROCESSOR_IDENTIFIER).
coresinteger or nullLogical cores available to the process.
rustcstring or nullOutput of rustc --version at run time.
clock_sourcestringWall-clock source: tsc, cntvct or instant.
runnerstringgithub-actions when GITHUB_ACTIONS is set, else local.

Benchmark entry

FieldTypeMeaning
namestringFully qualified name, group::name or just name. Arguments appear as name/<arg>.
layersarrayOne entry per layer that produced a result. Layers that were unavailable are omitted.

Layer entry

FieldTypeMeaning
layerstringWallClock, Allocations, AllocBytes, HwInstructions, HwL1Misses, HwL2Misses or HwBranchMisses.
meannumberMean per-iteration value. Nanoseconds for WallClock, counts for the others, bytes for AllocBytes.
std_devnumberSample standard deviation of the accepted values.
mediannumberMedian of the accepted values.
ci_lownumberLower bound of the 95 % confidence interval for the mean.
ci_highnumberUpper bound of the 95 % confidence interval for the mean.
samplesintegerNumber of accepted samples.
valuesarrayThe accepted per-iteration values, in arrival order.
outliersintegerNumber of samples rejected by the MAD test.
iters_per_batchintegerIterations executed in each measured batch.
stop_reasonstringconverged, max_samples or max_time.
noisybooleantrue when the noise-regime SPRT did not accept the clean hypothesis.

Non-finite numbers (NaN, infinities) are written as null. In practice this appears only for degenerate inputs such as a benchmark whose mean is zero.

Example

{
  "schema_version": 2,
  "tool": "tpt-benchmark",
  "tool_version": "0.1.0",
  "environment": {
    "commit": "9f2c1ab0d4e5",
    "timestamp": "2026-11-23T04:05:06Z",
    "os": "linux",
    "arch": "x86_64",
    "cpu": "AMD EPYC 7763 64-Core Processor",
    "cores": 4,
    "rustc": "rustc 1.91.0 (f1e2d3c4b 2026-10-01)",
    "clock_source": "tsc",
    "runner": "github-actions"
  },
  "benchmarks": [
    {
      "name": "sums::sum/128",
      "layers": [
        {
          "layer": "WallClock",
          "mean": 412.7,
          "std_dev": 3.1,
          "median": 411.9,
          "ci_low": 411.8,
          "ci_high": 413.6,
          "samples": 37,
          "values": [412.0, 409.5, 415.2],
          "outliers": 2,
          "iters_per_batch": 2560,
          "stop_reason": "converged",
          "noisy": false
        }
      ]
    }
  ]
}

(values is shortened here. A real export lists every accepted value.)

Compatibility

  • Schema 2 is schema 1 plus the environment object. Nothing in benchmarks changed, so a reader written for schema 1 can read schema 2 files by ignoring the new field. A reader of schema 2 must treat a missing environment (a schema 1 file) as unknown.

  • Adding an optional field is not a breaking change, and does not bump the version.

  • Renaming or removing a field, or changing a unit, bumps schema_version.

  • Golden-file tests in crates/tpt-benchmark/src/json.rs guard the layout.

Built with tpt-benchmark. Hosted CI runners are noisy and usually have no hardware counters, so compare trends on one machine rather than absolute numbers.
